Cutting Rust target/ by 61–82% without dropping debug info

Large Rust repositories routinely chew through 30–100 GiB of disk across feature flags, test targets, and branch switches. I built two separate prototypes inside forks of Cargo, rustc, and the Wild linker—keeping full DWARF debug information and incremental compilation enabled—and measured both storage saved and exact rebuild cost across Bevy, Polars, Nushell, Ruff, and uv.

1. Cargo: active artifact retention (-Zactive-artifacts)

Cargo tracks the complete artifact graphs needed by live sessions, published outputs, and registered executions. When a configuration switch succeeds, Cargo reclaims recorded units that no longer have a live owner. If a build fails, the previous successful session roots stay intact so a broken edit never evicts your working build.

Across five matched histories—running identical sources, edits, flags, compiler, and CPU—active retention cut disk usage by more than 60% on every repository. Warm check, build, test, and clippy runs reused 100% of cached artifacts with zero extra recompilation. The explicit tradeoff is paid only when returning to an evicted configuration for the first time.

2. rustc & Wild: compact compiler artifacts

Retention solves multi-configuration sprawl, but even a single build is bloated by duplicated object files, uncompressed metadata, and serialized dependency-graph lookup tables. This second prototype shrinks the artifacts themselves:

  • Compressed objects & metadata — Zstd-compressed ELF objects, rmeta, and incremental artifacts while keeping compressed .dwo debug files readable by gdb.
  • Content-addressed object & debug storage — Ordinary ELF objects stored by content hash instead of copied across archives.
  • Direct compact linking in Wild — Wild reads the compact library representation straight from disk without expanding archives before linking (this work also uncovered and fixed Wild debug-compression segment padding bug #2616).
  • In-memory dep-graph index — rustc rebuilds the dependency-graph lookup index in memory rather than persisting redundant index tables to disk.
