A document people can work with

Typst combines a typesetter with a programming language. Functions and templates make the layout reusable. The Office work extends that control to the files people exchange: briefs, papers, tables, and slide decks.

Bring existing Office files into source

The importers read arbitrary DOCX and PPTX packages. They resolve styles, numbering, media, slide masters, and theme colors before they produce Typst source and extracted assets.

DOCX import recovers a flowing document. PPTX import preserves authored coordinates by default and produces Touying slides. A second mode promotes recognized placeholders into source that follows the slide’s content flow.

The loss report names each known approximation or dropped object. Charts can become data tables or plots. Comments and revisions survive as metadata. EMF/WMF media, animations, transitions, and embedded OLE objects remain gaps.

Let someone edit in Word, then return to Typst

The review exporter tags source regions and keeps a separate baseline. After a reviewer edits the DOCX, a three-way comparison finds the Word change, the original text, and any local source edits.

Plain source text in headings, paragraphs, lists, table cells, headers, footers, and footnotes can return to its original location. Existing style wrappers stay intact. Repeated review cycles retain the same workflow.

Formatting changes, structural changes, and ambiguous source matches produce conflicts. The importer escapes literal text before it writes Typst. Word comments stay review annotations.

The rest of the Office work

Research documents

Headings and styles, equations, tables, citations, bibliographies, cross-references, contents, notes, page sections, headers, and footers. These are the structures that make a brief or paper useful after export.

Decks and graphics

Native text, shapes, gradients, images, tables, equations, placeholders, and speaker notes. SVG carries a PNG compatibility fallback. Complex diagrams and transforms use positioned images.

Local browser export

Rust runs as WebAssembly. A source file, project folder, or ZIP stays in browser memory. Relative imports, binary assets, bundled fonts, and vendored packages keep their paths. The hosted demo exports DOCX and PPTX.

Reports and acceptance limits

Reports distinguish native, approximate, rasterized, and dropped content. CLI limits can reject an export with too many recorded losses. Native paragraph reflow and font substitution still require a check in Office.

Pandoc and compiler performance branches

The fork also contains a typed Pandoc JSON target. It evaluates Typst before export, but remains incomplete and unsupported. The HarfRust and line-break performance work lives on a separate branch. This page makes no speed claim for that branch.
